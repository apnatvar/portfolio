# Portfolio guidelines

## Project entry structure

For each project, state the project name, accurate category, AP's role, work performed, and a link to the live site or repository where available. Keep descriptions compact and verifiable.

## Evidence levels

- **Implementation evidence:** describe features, systems, or code delivered when supported by the project source or records.
- **Prototype/research:** label proof-of-concepts and academic work explicitly; do not present them as deployed client outcomes.
- **Outcome evidence:** include measured traffic, ranking, revenue, or performance only with a dated source, a clear measurement window, attribution context, and approval to publish.

Existing portfolio descriptions are source material, not independently audited case studies. Present them as descriptions of work, not as third-party verification or proof of commercial impact.

## Confidentiality and links

Respect client confidentiality and remove private data from screenshots, logs, and repositories. Prefer durable first-party project links. Say when a project link is a repository, thesis, prototype, or case-study document.

## Service alignment

Use projects to illustrate relevant implementation experience, then link to the closest service. Do not imply each listed project is an SEO engagement or that a portfolio project generated a specific business result unless evidence supports that claim.
